How it works

Behavioral, not signature-based.

Hound doesn't rely on known-bad lists. It understands what each type of workflow is supposed to do — and flags when behavior falls outside that scope.

01 — Observe

Every execution is classified

Hound identifies the source of each command: Claude Code, Cursor, an npm install, a terminal session, or a shell script. Each source has an expected behavioral profile.

02 — Evaluate

Scope violations are detected

When a process does something outside its expected scope — reads credentials, installs persistence, makes unexpected network calls — Hound flags it. Normal builds and installs produce zero output.

03 — Record

A trace is written, permanently

Every session gets a plain-English trace stored locally. Clean sessions are logged as clean. Notable sessions explain what happened, what was targeted, and how it was caught.

Why not just use an antivirus?

Different tools. Different questions.

Traditional security tools ask "is this known malware?" Hound asks "is this consistent with what this workflow should be doing?" Those are different questions with different answers.
